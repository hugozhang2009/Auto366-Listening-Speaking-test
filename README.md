# 天学网自动口语答题程序

从零开发的天学网在线考试口语答题自动化程序，覆盖 PartA、PartB（三问 + 五答）、PartC 完整环节。程序通过精确倒计时、音频播放控制，配合天学网平台的时间线完成答题流程。

> **本项目处于需求设计阶段，暂无已实现的源代码，诚邀开发者从零开始完整实现。**



---

## 项目概述

本程序用于自动化执行天学网（Up366）平台的口语考试环节。考生登录天学网后，平台会将试题资源下载到本地，程序通过读取本地试题文件并按既定流程播放音频、控制倒计时，辅助完成听力口语答题。

## 环境前置要求

### Up366StudentFiles 目录结构

天学网平台在用户机器上会以自定义路径存储试题资源。程序需要读取以下目录结构：

```
{自定义根目录}\Up366StudentFiles\flipbooks\
└── {题目HashID}\
    ├── questions\              ← 核心文件夹，程序从这里读取题型数据
    │   └── {随机Hash}\        ← 每个题型一个子文件夹
    │       ├── media/
    │       │   ├── *.mp4      # 视频文件（PartA / PartB 视频）
    │       │   ├── *-ZC.mp3   # 答案/原文音频（如 1-ZC.mp3）
    │       │   ├── X.Y.1.mp3  # 第 Y 题第 1 种答案（如 2.1.1.mp3）
    │       │   ├── X.Y.2.mp3  # 第 Y 题第 2 种答案（如 2.1.2.mp3）
    │       │   └── *.mp3      # 其他音频（如作者问题哈希文件）
    │       └── net/
    │           └── psdata*/answer.json
    └── bookres\media\          ← 固定提示音频目录
        ├── 1welcome.mp3        # 欢迎语
        ├── 2partazhishi1.mp3   # PartA 介绍语
        ├── 3parta1min.mp3      # 1分钟准备提示
        ├── 4parta1again.mp3    # 再听一遍提示
        ├── 5parta1read.mp3     # 现在开始录音提示
        ├── beep.mp3            # beep 提示音
        ├── 6partbzhishi.mp3    # PartB 介绍语
        ├── 7partbsanwen.mp3    # 三问提示
        ├── 9partbwuda.mp3      # 五答介绍语
        ├── 10partczhishi.mp3   # PartC 介绍语
        └── 11partcretell.mp3   # PartC 提示音
```

**关键说明：**

- `{自定义根目录}` 由用户在程序启动时选择，默认为天学网客户端配置的 `Up366StudentFiles` 存放路径（如 `E:\Up366StudentFiles`），不同用户的安装路径可能不同。
- 程序启动后，用户需指定 **questions 文件夹** 和 **固定音频文件夹（bookres/media）** 的完整路径。
- 盘符不固定，可能是 C:、D:、E: 等，程序需支持任意盘符。

## 功能需求

### 1. 用户界面

| 组件 | 说明 |
|------|------|
| 地址栏 | 输入 questions 文件夹路径，需以 `<根目录>\Up366StudentFiles\flipbooks` 开头，且文件夹名为 `questions`；不符合要求时地址栏文字变红并显示"请重新选择文件夹" |
| 浏览按钮 | 调用系统文件资源管理器，选择后自动填充地址栏 |
| 固定音频路径框 | 手动输入或浏览选择 `bookres/media/` 目录 |
| 视频播放窗口 | 嵌入视频控件，静音播放 PartA mp4 视频（使用 tkinter 内嵌 opencv/vlc 均可） |
| 确认提示文本 | "请根据 PartA 内容确认是否为本套试题答案" |
| 启动按钮 | 点击后隐藏界面元素，进入自动化流程，显示日志输出区 |
| 日志输出框 | 每条日志以当前时间戳开头（格式 `HH:MM.ss`），支持实时更新倒计时（`\r` 不换行刷屏） |
| 暂停/继续按钮 | 启动后可点击暂停或恢复流程 |
| 退出按钮 | 随时终止程序 |

### 2. 题型分类规则

遍历 `questions` 下所有一级子文件夹，按以下优先级识别：

| 类型 | 识别规则 | 预期数量 |
|------|---------|---------|
| **PartA** | `media` 中同时存在 `.mp4` 文件 和 `1-ZC.mp3` | 1 |
| **PartC** | `media` 中存在文件名含 `partc`（不区分大小写）的 `.mp3` | 1 |
| **三问（PartB）** | `media` 中存在 `2.X-ZC.mp3`（X=1/2/3），按 X 升序排列 | 3 |
| **五答（PartB）** | `media` 中存在 `3.X-ZC.mp3`（X=1~5），按 X 升序排列 | 5 |

缺失题型时输出警告但继续执行已有部分。

### 3. 固定音频时长预读取

程序启动后**立即**读取 `bookres/media/` 下所有固定音频的时长（秒），存储在变量中供倒计时使用。推荐使用 `mutagen` 或 `pydub` 读取。若文件缺失则弹窗报错并终止。

### 4. 完整执行流程（27 个阶段）

| 阶段 | 时长来源 | 说明 |
|------|---------|------|
| 1. 欢迎语等待 | `1welcome.mp3` 时长 | 倒计时，不播放音频 |
| 2. PartA 介绍语等待 | `2partazhishi1.mp3` 时长 | 倒计时，不播放音频 |
| 3. PartA 视频播放 | 视频实际时长 | **静音**播放 PartA mp4 |
| 4. 1分钟准备 | 固定 60s | 倒计时 |
| 5. 再听一遍提示等待 | `4parta1again.mp3` 时长 | 倒计时 |
| 6. 5秒准备 | 固定 5s | 倒计时 |
| 7. 再次播放 PartA 视频 | 视频实际时长 | **静音**播放 |
| 8. 录音提示等待 | `5parta1read.mp3` 时长 | 倒计时 |
| 9. 5秒准备 | 固定 5s | 倒计时 |
| 10. beep 提示音等待 | `beep.mp3` 时长 | **静音**等待 |
| 11. 播放 PartA 答案 | `1-ZC.mp3` 时长 | **正常播放** |
| 12. PartB 介绍语等待 | `6partbzhishi.mp3` 时长 | 倒计时 |
| 13. 3秒准备 | 固定 3s | 倒计时 |
| 14. PartB 视频播放 | 视频实际时长 | **静音**播放（从含 mp4 的三问文件夹中定位） |
| 15. 三问提示等待 | `7partbsanwen.mp3` 时长 | 倒计时 |
| 16. 三问循环（×3） | 见下方 | 每题重复以下6步 |
| 17. 五答介绍语等待 | `9partbwuda.mp3` 时长 | 倒计时 |
| 18. 五答循环（×5） | 见下方 | 每题重复以下6步 |
| 19. PartC 介绍语等待 | `10partczhishi.mp3` 时长 | 倒计时 |
| 20. 15秒准备 | 固定 15s | 倒计时 |
| 21. PartC 原文播放（第一次） | `partc-ZC.mp3` 时长 | **静音**等待 |
| 22. 2秒准备 | 固定 2s | 倒计时 |
| 23. PartC 原文播放（第二次） | `partc-ZC.mp3` 时长 | **静音**等待 |
| 24. 60秒准备 | 固定 60s | 倒计时 |
| 25. PartC 提示音等待 | `11partcretell.mp3` 时长 | **静音**等待 |
| 26. beep 提示音 | `beep.mp3` 时长 | **正常播放** |
| 27. 播放 PartC 答案 | `partc-ZC.mp3` 时长 | **正常播放** |

### 5. 三问流程（每题，共3题，按题号升序）

1. 等待 20 秒准备
2. **静音**等待 beep 提示音
3. **随机**选取当问一个答案音频播放（时长 ≤ 10s），播放结束后等待 `max(0, 10 - 答案时长)` 秒补齐 10s
4. **静音**等待作者回答（`2.X-ZC.mp3`）
5. 等待 2 秒
6. **静音**再次等待作者回答

### 6. 五答流程（每题，共5题，按题号升序）

1. **静音**等待作者问题音频
2. 等待 2 秒
3. **静音**再次等待作者问题音频
4. 等待 10 秒准备
5. **静音**等待 beep 提示音
6. **随机**选取当问一个答案音频播放，播放结束后等待 `max(0, 10 - 答案时长)` 秒补齐

### 7. 多答案选取策略

- 三问和五答每个题目有多个答案文件（`.1`、`.2` 等），程序应**随机选取**一个播放（`random.choice`），增加每次运行的变化性。
- 若某题答案列表为空，输出错误日志并跳过该题。

## 技术要求

| 项目 | 要求 |
|------|------|
| **语言** | 不限，Python / TypeScript / C# / Go 等均可，推荐 Python（有 tkinter 生态优势） |
| **GUI 框架** | Python 可选 tkinter / PyQt；TS 可选 Electron；C# 可选 WinForms/WPF |
| **音频处理** | 读取时长（`mutagen` / `ffmpeg.probe` / `ffprobe`）+ 播放（`playsound` / `pydub` / `vlc` / `napi-mediaplayer`） |
| **视频播放** | 静音播放 mp4，可选 opencv / vlc / ffmpeg + GUI 内嵌 |
| **日志刷新** | 同一行实时更新倒计时（`\r` 或定时器刷新 UI 控件），避免刷屏 |
| **暂停机制** | 暂停期间倒计时和等待均暂停，恢复后继续 |

## 注意事项

- 程序必须与天学网平台实际考试时间线精确同步，倒计时需精确到毫秒级。
- 路径中的 `Up366StudentFiles` 目录是用户自定义根目录下的子目录，不同用户路径不同，程序启动时需让用户指定根目录或直接定位到 questions 文件夹。
- 若缺少某些题型文件（如三问不足3个），程序应输出警告并继续执行已有部分，不应崩溃。
- 欢迎各路开发者基于此需求文档开发展示方案，也可提供不同语言/框架的实现版本。
